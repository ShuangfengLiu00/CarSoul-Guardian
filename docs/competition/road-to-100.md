# Road to 100 · GOAI 满分冲刺开发计划

> 基线：80.5 / 100（2026-08-04 按官方参赛手册第 10 章实测）
> 目标：复赛提交 ≥ 90，决赛路演 ≥ 93
> 评审口径：行业场景价值 25% · Agent能力与任务闭环 25% · 产品体验与Demo 20% · 技术深度 15% · 安全合规 10% · 开放复用 5%

## 〇、诚实的天花板说明

最后 5–7 分不是工程问题，是**真实世界证据**问题：真实车辆数据接入、真实用户规模验证、车厂/保险/4S 合作背书。工程能做到 93–95；冲 97+ 必须从第一周就启动外部验证（见 W1.3 / W3.2），否则到决赛也补不上。

---

## 一、Phase 1 · 初赛冲刺（8.4 – 8.16，剩余 12 天）

初赛必交：500 字作品简介 + 方案 PPT；可选：Demo 视频、代码包。初赛不强制可运行代码，评的是**方向与场景价值**——这 12 天的分数全在材料上。

| # | 工作项 | 对应条款 | 工作量 | 验收标准 |
|---|--------|----------|--------|----------|
| W1.1 | 500 字作品简介（按附录 A 一页纸结构） | 5.2 必交 | 0.5 天 | 含目标用户/核心问题/方案/创新点/开放复用价值/进展，500 字内 |
| W1.2 | PPT v3：叙事顺序对齐官方权重 | 10.1 | 1.5 天 | 第 1 章场景价值（25%）→ 第 2 章 Agent 闭环（25%）→ Demo（20%）→ 技术（15%）→ 合规（10%）→ 开源（5%）；现 PPT v2 按自创六维写的，需重排 |
| W1.3 | 真实车主访谈启动（10–20 人） | 10.1 场景价值 | 持续 | 访谈纪要 + 痛点引用，写进 PPT 第 1 章和复赛方案 |
| W1.4 | 3 分钟真实链路 Demo 视频 | 5.2 可选 / 附录 C | 1 天 | 真实后端 + 真实交互 + 一个异常分支（如 LLM 降级）；画面角标"模拟车辆数据演示" |
| W1.5 | mock 标注体系 | 第 11 章红线 | 0.5 天 | 故事模式页面加"演示模式·模拟数据"水印；PPT/视频同步标注；消除"虚假演示"红线隐患 |
| W1.6 | 《数据来源与合规说明》v1 | 6.2 复赛必交 | 1 天 | 数据类型/来源/授权/脱敏/模拟逻辑与适用边界（Q7 三要素）/行业边界 |
| W1.7 | 商业 API 与依赖披露 | 第 9 章 | 0.5 天 | OpenAI 调用环节/费用假设/可替代性（离线降级+本地模型方案）/锁定风险；第三方依赖+License 清单 |
| W1.8 | 价值量化测算写进简介与 PPT | 10.1 "价值收益" | 0.5 天 | 一笔账：过度保养年均浪费 + 重大故障提前发现的避免损失 + 二手车残值管理收益 |

**Phase 1 出口检查**：8.15 封版前跑回归脚本（见 W0），材料与 Demo 一致性互查（附录 C 清单逐项过）。

## 二、Phase 2 · 复赛工程化（8.17 – 9.3）

复赛必交：更新方案 + 可运行 Demo + 代码仓库 + 合规说明。评委开始跑代码、查仓库——这阶段把工程缺口全部焊死。

| # | 工作项 | 对应维度 | 工作量 | 预期提分 | 验收标准 |
|---|--------|----------|--------|----------|----------|
| W2.1 | 记忆与 ActionStore 持久化（SQLite） | Agent闭环 / 8.4 | 2 天 | +1.5 | 重启后 episodic/skill/evolution 记忆与审计账本可恢复；补持久化测试 |
| W2.2 | 专家交叉质疑（rebuttal 轮） | Agent闭环 | 2 天 | +1 | 高严重度 finding 触发其他专家确认/反驳，governance Judge 仲裁；trace 可见完整辩论链 |
| W2.3 | 多模态：拍照识别仪表盘故障灯 | 技术深度 / 1.2"特别欢迎" | 3 天 | +2 | 照片 → 视觉模型 → DTC/故障灯识别 → 知识库 → 建议；前端拍照上传入口；无 Key 时样本图降级演示 |
| W2.4 | 本地小模型兜底（Ollama/Qwen） | Agent闭环 | 1 天 | +0.5 | 无网无 Key 时仍走 LLM 而非纯规则；写进"可替代性"披露 |
| W2.5 | 前端关键路径测试（Vitest） | Demo 完成度 | 1.5 天 | +0.5 | 闭环渲染、告警确认、反馈提交三条链路有测试 |
| W2.6 | 三套 mock 收口为统一 fixture 层 | Demo 完成度 | 1 天 | +0.5 | demoData/holoData/storyData 单源化，真实 API 与演示数据边界一目了然 |
| W2.7 | 评测指标表 | 8.2-6 验证与反馈 | 1 天 | +0.5 | 预测准确率/误报率/响应时延/工具调用成功率实测数据，写进复赛方案 |
| W2.8 | GitHub 公开仓库 + 开源三件套 | 开放复用 | 1.5 天 | +1.5 | 仓库公开；① vehicle-digital-twin JSON Schema ② 专家会诊 prompt 模板包 ③ StateGraph mini 独立示例；英文 README |
| W2.9 | 数据落地路线图 | 场景价值 | 0.5 天 | +1 | 车厂接口（主）/ 后装 OBD（备）/ 保险·4S 渠道（对冲）三线并行进 PPT |
| W2.10 | 追问澄清式多轮交互 | Agent闭环 | 1.5 天 | +0.5 | 信息不足时 Agent 主动追问（哪年的车/最近是否涉水），而非直接给结论 |

**Phase 2 出口检查**：9.2 封版回归；邀请 1 名外部人员按 README 从零复现 Demo（模拟验收）。

决赛评：展示效果、现场答辩、产品体验、落地潜力。现场演示是最大风险敞口，全部做双保险。

| # | 工作项 | 对应条款 | 工作量 | 验收标准 |
|---|--------|----------|--------|----------|

| W3.2 | 用户验证数据回收 + PoC 意向 | 落地潜力 | 持续 | W1.3 访谈对象的试用反馈报告；争取 1 份渠道合作意向（4S 店/汽修连锁/保险代理），哪怕是意向书 |

## 六、关键风险

1. **多模态（W2.3）是 3 天估期里最可能超支的**——若 8.25 前未跑通，降级为"语音问车"（ASR 成熟、半天可接），保住多模态这 2 分。
2. **PoC 意向（W3.2）不可控**——第一周就要开口谈，谈不下来就用 20 人试用报告兜底"真实验证"叙事。
3. **现场网络**——决赛 Demo 默认按"无公网"设计，本地小模型（W2.4）因此不只是加分项，是保险。
